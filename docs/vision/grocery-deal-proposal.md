# 湾区智能买菜助手 — 产品 Proposal

> 状态：Proposal（概念验证阶段）
> 日期：2026-02-19
> 定位：独立现金流产品，个人创业能力 test run

---

## 一句话

帮湾区家庭把每周超市 flyer 看完，直接告诉你该买什么、去哪买、怎么省钱。

## 要解决的问题

湾区家庭每周都在做同一件低效劳动：翻 Costco coupon book、刷 Safeway weekly ad、看 Ranch 99 传单、微信群里问"这周哪儿的肉便宜"。信息是公开的，但散落在十几个地方，比价全靠人脑。

现有工具（Flipp、各超市 app）只是把纸质传单数字化了——用户还是得自己翻。相当于把报纸搬上网叫数字化转型。

## 核心思路

用户不应该看任何 flyer。产品帮用户把 flyer 看完，输出的是决策，不是信息。

**Proactive 模式（优先做）**：每周主动推送本周最佳 deal + 购物路线建议。用户什么都不做就能收到。零启动门槛。

**Query 模式（后续加）**：用户主动问"这周想做红烧肉，去哪买便宜"、"Costco 这周值得去吗"，产品基于已解析的数据回答。

## 用户分群

按主力超市分群，每群的内容策略不同：

**Costco 用户** — 关注新品和 coupon book，购物频率低（两周一次），单次消费高。推送跟着 coupon book 周期走。

**Safeway / Albertsons 用户** — 关注 weekly ad + digital coupon 叠加，每周购物，对单品价格敏感。强调"比上周降了多少"。

**Ranch 99 / 华人超市用户** — 关注生鲜时令价格，尤其肉类海鲜。决策逻辑是"先看什么便宜再决定做什么菜"。这是产品最能发力的场景。

**Whole Foods 用户** — 价格敏感度低，关注 Amazon Prime 折扣和有机品类。

## 数据来源

所有数据均为公开信息：

- 各超市 weekly ad / digital flyer（大部分有线上版本，最差可 scrape 或 OCR）
- Costco coupon book（定期发布）
- 线上渠道：Weee!、Instacart、Amazon Fresh 的价格和促销

数据处理的核心工作：flyer 图片 → 结构化数据（商品名 / 原价 / 折扣价 / 单位 / 有效期 / 门店），品类归一化（跨超市同商品识别），价格历史积累（判断"真打折"还是"假打折"）。

## 区域策略

按湾区主要华人聚居区逐区推进：

- South Bay（Cupertino / Sunnyvale / Santa Clara）
- East Bay（Fremont / Newark / Union City）
- Peninsula（San Mateo / Foster City）

每个区域的超市组合和购物动线相对固定，先用本地常识手动规划路线，后续接地图 API 做个性化。

## 线上线下混合

不只是线下超市比价，也整合线上渠道。混合推荐的差异化示例："排骨在 Weee! 上 $3.99/lb 包邮，比 Ranch 99 门店便宜 $1，但到货要两天。今晚要用去店里，周末做就线上买省 $5。"

这种跨渠道决策帮助目前没有任何工具在做。

## 产品形态

MVP：微信群 bot 或公众号，每周推送。最简单的载体，最低的开发成本。

**第一版完全可以是人工运营** — 每周手动看 flyer、编辑推荐、发到群里。用户感知到的是"智能推荐"，背后是 Wizard of Oz。AI 逐步替换人工环节，每一步确保用户体验不降级。

## 产品演进路径

**第一层：折扣聚合 + 智能推荐**
纯数据产品。这周什么值得买、去哪买、顺路逻辑。价值 = 省钱 + 省时间。数据源全部 open。不需要任何用户输入即可工作。

**第二层：个性化 shopping list**
学习用户购买模式。你家每周固定买的东西 + 本周折扣叠加。从"推荐"变成"替你决定"。数据从用户行为中自然积累（点了哪些推荐、忽略了哪些）。

**第三层：菜谱反推**
折扣驱动菜单，菜单驱动购物清单。菜谱库是 open data，叠加用户口味偏好。这一层开始需要跨域关系推理（折扣 × 菜谱 × 偏好 × 库存 × 季节），产品复杂度显著上升。

**第四层：营养管理**
家庭成员的营养需求、健康目标、饮食限制。从"省钱吃好"到"吃得健康"。需要深度家庭画像，用户数据通过前三层自然积累，不需要用户主动填写。

## 变现路径

**短期** — 免费工具，微信群 / 小红书口碑传播。湾区华人社区传播效率高，实用工具容易自发扩散。

**中期** — Affiliate 分成。Instacart、Weee!、各超市 pickup/delivery 的 referral 机制。用户通过推荐链接下单，产品拿分成。不需要大用户量即可产生现金流。

**长期** — B2B 广告 / Targeted promotion。本地超市（尤其华人超市）数字化营销能力弱，仍在花钱做报纸广告和传单。产品拥有"这周谁在找什么食材"的精准意图数据，可向超市或品牌方售卖 targeted promotion。

## 核心指标

- 可量化的价值主张："按推荐买，这周比随便买省了 $X"
- 用户留存：每周推送的打开率和互动率
- 第一块钱：affiliate 分成到账

## 执行计划

**第 1 周**：建一个微信群，手动发 Ranch 99 + Costco 本周 deal 汇总，拉 20 个朋友进来。

**第 2-4 周**：观察互动，调整内容。什么品类最受关注？什么格式最易读？推送频率是否合适？

**第 1 个月末**：如果群活跃，开始写脚本自动抓取 flyer 数据，减少手动工作。如果群沉默，低成本 pivot 或放弃。

**第 2-3 个月**：自动化数据采集 + 结构化，接入更多超市，尝试第二个区域。接入 affiliate 链接测试变现。

## 风险与假设

**假设 1**：湾区华人家庭确实会因为折扣信息改变购物行为。（通过 MVP 验证）

**假设 2**：flyer 数据可以稳定、低成本地获取和结构化。（通过第一个月的技术验证）

**假设 3**：微信群 / 公众号是合适的触达渠道。（可能需要测试其他渠道如小红书、Telegram）

**风险**：超市调整 flyer 发布方式导致数据源断裂；竞品（Flipp 等）开始覆盖华人超市；用户新鲜感消退后流失。

## 与 CKG 的关系

本产品不依赖 CKG，也不为 CKG 服务。独立的现金流项目，独立的创业 test run。

如果产品演进到第三层（菜谱反推）及以上，信息复杂度自然增长到可能需要 CKG 式的关系编码和 multi-hop 推理。届时是否引入 CKG 取决于实际需求，不预设。
