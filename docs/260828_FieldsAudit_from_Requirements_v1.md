# 需求清单 —— 从需求推字段

2026-08-28 · 配套 `260828_FieldSet_v1.md`

---

## 这份文档回答什么

四份文档的分工：

| 文档 | 回答的问题 | 方向 |
|---|---|---|
| **本文档** | **我们要回答用户什么问题，为此需要知道什么** | 倒推（需求 → 字段）|
| `260808_FieldAudit_v2.md` | 源上有什么 | 正推（字段 → 需求）|
| `260828_FieldSet_v1.md` | 我们决定要哪些格子 | 两者的交集 |
| `260807_Ingestion_Design_v3.md` | 怎么抓 | — |

**它的用途不是「筛掉没用的字段」，是「验证有没有需求落空」。**

两个用途价值不一样：
- 筛掉没用的字段 —— 低价值。多留一列的代价 << 少一列的代价，而且原则本来就是「填的越多越好，没有的空着」
- **验证没有需求落空 —— 高价值。这是唯一能发现「我们做不到什么」的方向**

所以这份文档该用在**字段集定完之后**，倒着走一遍找缺口，不是用在前面筛字段。

---

## 方法

```
正推（字段视角）  拿着字段问：这个字段回答哪条需求？没有 → 不抓，理由可复查
倒推（需求视角）  拿着需求问：这条需求有哪列接住？没有 → 缺口
```

**同一棵树走两遍，方向相反，所以不循环。** 而且第二遍能抓到第一遍抓不到的：

一个字段在筛选时被判「有用」，不代表它**真的满足**那条需求。比如 Flipp 的 `description`
挂在「规格」这条需求上——筛选时它是有用的，但它是自由文本，能不能真解析出规格另说。
**只有从需求那头走回来，才会问出「规格这条，Flipp 那边真的接住了吗」。**

倒推的产出有两类：

```
需求 → 没有任何列          缺口
需求 → 有列但形态不可靠     半缺口（要标风险）
```

### 拆到什么程度

**拆到能指着一个具体东西为止。** 「值不值」当标题挂着指不向任何字段，
拆到「跟别家比 → 要单价 → 要规格」才会撞出 `netWeight`。

三月漏掉 `netWeight` 不是因为没写「值不值」，是因为没往下拆到「要规格」。
**停在标题层，等于倒推没做。**

### 叶子分四类，只有一类进字段表

```
从一条商品记录里抄下来的     → 进字段表
处理规则（单位归一、区间取两端）→ normalization
一个方法（认出同一件商品）    → 单列一件事
限制（历史里只有特价）        → 已知不确定
```

**门店坐标、历史基线、模型版本不进抓取字段集** —— 那些不是从一条商品记录里抄的东西。

## 一、什么 —— 这到底是个啥东西

```
什么
├─ 它是什么
│   ├ 广告上印的名字（英文 / 中文）
│   ├ 品牌
│   ├ 品类（鸡蛋 / 洗衣液 / 泡面）──→ 归分类那条线，不在这重复
│   └ 口味 · 品种 · 型号
│         ⚠️ 传单主动模糊：`Selected varieties.`（Safeway 大量）
│            传单说「多种口味」，不说哪几种 —— 商家不承诺，不是我们抓漏了
│
├─ 是不是我要的那个
│   ├ 一个名字盖多个商品
│   │     `Pepperidge Farm Goldfish Crackers or Crisps`（两个东西一个广告名）
│   │     `YEOS DRINK SERIES` 一格挂 10 个编码
│   └ 名字是广告名，不是货架上的名
│
└─ 我到店里认得出来吗
    ├ 名字能不能对上货架
    ├ 商品图
    └ 中文名（99 Ranch 有真简繁中文名）
          湾区华人家庭是目标用户 → 产品决定，不是技术问题
```

**已定**：`Selected varieties` 以传单为准，照抄不展开。中文名要。

## 三、何时 —— 什么时候有效

```
何时
├─ 这个价的有效期
│   ├ 起始日 · 截止日
│   └ ⚠️ **同一份传单不同页的有效期不同**（2026-08-28 实测 11 页）
│         p03 Monthly  07.24–08.20   近一个月
│         p02 Weekend  08/14–08/16   3 天
│         p04 生鲜      08.14–08.20   1 周
│         其余          08.07–08.20   2 周
│         接口一律报 Aug.14-Aug.20 —— **11 页里 10 页跟接口不一致**
│
├─ 今天还算不算数
│      过期数据比没有数据更糟
│
├─ 什么时候换新的
│      Flipp 三家约周三 · 99 Ranch 约周五（没系统验证）
│
└─ 限时 · 限日
      `Friday. Saturday. Sunday ONLY`（p02 印在页面级横幅上）
      ⚠️ 目前只见过页面级，没见过单品级
```

**已定**：有效期以图上印的为准，接口日期当第二来源，不一致就告警。
**坑**：日期有 5 种格式（`08/07/26` `07.24` `08.14` `08.07.2026` `08.07`），要归一。

**这条的坑**：有效期内 ≠ 有货。库存不印在传单上，我们永远不知道。

## 四、值不值 —— 这个价格好不好

```
值不值
│
├─ 一、算出一个能比的数：单价 = 我付多少 ÷ 我拿到多少
│  │
│  ├─ 我付多少 —— 不是印上去那个数
│  │   ├ 印的价
│  │   ├ 拿到这个价的条件 ──→ 【资格门槛】
│  │   └ 附加费（CRV 押金、税）—— 并进「资格门槛」，不单列
│  │
│  └─ 我拿到多少
│      ├ 先分岔：按量卖 还是 按包卖
│      │   ├ 按量卖  $4.99/lb → 单价就是印的数，不用除
│      │   │        ⚠️ 陷阱：「6 lbs. or more」是购买门槛，不是包装规格
│      │   └ 按包卖  → 往下走
│      ├ 规格数值 + 单位
│      ├ 单位类别：重量 / 体积 / 计数，三类不能互换
│      │   ⚠️ `foz`（液量盎司）≠ `oz`（重量盎司），商品库里 740 条（11%）
│      ├ 套娃：件数 × 每件多大        12-pack × 12 oz
│      ├ 区间：是两个数不是一个        24.3 to 27.3 oz
│      │   ⚠️ Safeway 本周 216 条里 47 条（22%）是区间，另三家 0 条
│      │      取下限则单价虚高：oz 类中位 1.36×、ct 类中位 1.67×、最大 8×
│      │      **45/47 带 `Selected varieties`** → 这不是「一件商品尺寸没写死」，
│      │      是「好几个商品共用一个价」——跟「一格多商品」是同一件事的两面
│      └ 一格多商品：一个价盖五种商品五种规格
│            `Té Lipton or Gatorade or Pepsi or Poppi or Alani`
│
├─ 二、找一个基准来比
│   ├ 跟别家同一件比      要跨店认出是同一件
│   ├ 跟它平时比          要跨周认出是同一件 + 历史（现在一条没攒）
│   │                     ⚠️ 陷阱：历史里只有特价 → 得出的是「比平时特价便宜」
│   │                        不是「比原价省」。强的省钱数字需要外部常规价源（P6，未建）
│   ├ 跟它原价比          Ranch 传单 12%（28/231）· Flipp `original_price` 0%
│   │                     （`price + dollars_off` 可还原 4%）
│   └ 跟同类替代品比      A 牌鸡蛋 vs B 牌鸡蛋
│                         要分类 + 实体识别。Luna 定：先进 V1 试，不行再挪后
│
└─ 三、比出来得站得住
    ├ 单位同类才能比
    ├ 两边都得在各自有效期内 ──→ 【何时】
    └ 限制：便宜 ≠ 值得买。绝对价高的「特价」照样不值
          这是心理价位，个人化的，不在抓取层
```

### Bundle 三分法（这一支的核心）

```
① 没有 bundle      一件一件卖
② 不可拆 bundle    几个单品绑成一份卖，不能拆      → 藏在规格的乘数里
③ 可拆 bundle      单品照卖，买够 N 件才有这个价    → multibuy
```

**单品 = 最小可买单位，不是最小物理个体。**

```
单价 = (印的价 ÷ 可拆bundle件数) ÷ (不可拆bundle个数 × 单品规格)
```

**包价和单位价是两列，不是二选一。** 虾一包 2 磅 $5.99 和 $3.00/磅同时成立。

## 五、资格门槛 —— 凭什么我能拿到这个价

```
资格门槛
├─ 拿到这个价要满足什么
│   ├ 会员身份            Flipp 149/482 = 31% 是会员价
│   ├ 买够 N 件           `2 PACKS $10` · `3 FOR $9.99` · `MUST BUY 4`
│   ├ 凑单（可跨商品）     `MIX & MATCH`
│   ├ 剪券 / 数字券        传单上的 `Clip Deals` 入口（那格不是商品）
│   └ 时间窗              ──→ 跟【何时】重叠，别重复记
│
├─ ⚠️ 条件会叠加
│      `BUY 1 GET 1 FREE MEMBER PRICE WHEN YOU BUY 2`
│      一条广告里「会员」+「买 2 件」同时成立，存成单值就丢一半
│
├─ 我最多/最少能买多少
│   ├ 限购上限            `Limit 8 items.` · 商品库 `purchaseLimit`
│   └ 起购量              `WHEN YOU BUY 6 OR MORE`
│
├─ 价格之外还要付什么     `+CRV (CA only)` · `EA +TAX & CRV`
│
└─ 细则里的坑
    ├ `EQUAL OR LESSER VALUE`  买一送一，送的按便宜的算
    └ `while supplies last`     ⚠️ 未确认四家印不印
```

**已定**：会员价属于资格门槛（不是「促销形式」另立一类）；数量上下限并入本条；
附加费并入本条；「促销形式」不是独立的一行，**它就是条件的取值**。

**这条的坑**：三分之一的商品价格带条件。不处理的话，我们给出的三分之一价格是**用户拿不到的价格**。

## 六、认出同一件商品 —— 两条记录是不是同一个东西

```
认出同一件
├─ 有没有稳定编号
│   ├ 全球唯一（真条码）    跨店 ✅ 跨周 ✅
│   │     99 Ranch 商品库长码 6,449 条
│   ├ 店内编号            跨 99 Ranch 门店 ✅（实测三家一致）· 跨商家 ❌
│   │     99 Ranch 短码 147 条，全是生鲜
│   └ 广告位编号          两个都 ❌
│         Flipp `id` 跨周重合 0 条
│
├─ 没有编号时靠什么
│   ├ 只剩名字
│   │     Safeway 上周 196 条、本周 216 条，按编号重合 0，按名字重合 74
│   │     → 靠名字只认得出三分之一
│   ├ 名字 + 品牌 + 规格 一起当钥匙
│   └ ⚠️ 名字每周换写法，这是靠名字的天花板
│
├─ 「同一件」怎么定义 —— 这个定义决定历史能不能攒
│   ├ **身份粒度 = normalization 之后那个单位**（Luna 定）
│   │     32oz 啤酒的 12pack 和 24pack 是同一件，比的是各自折算的单瓶价
│   ├ ⚠️ 区间折算不出唯一单品规格（`24.3 to 27.3 oz`）→ 那类没有身份
│   └ 品种收窄算同一件（`Crackers or Crisps` → `Crackers`），只要其它内容匹配
│
└─ 跨店比跨周更难
      各家写法不同，同一件商品四家店四个名字
      ⚠️ 从没验证过跨店匹配能到什么水平
```

**已定（生鲜）**：身份键 = **整条英文名 + 状态 + 等级**。两条记录都没等级时算匹配
（否则 88% 的生鲜永远配不上对）。不拆商品名——`JUMBO` `PREMIUM` 印在名字里，
抽出来需要判断，留给解析层。

**条码是匹配键，不是身份键**：12pack 和 24pack 条码不同但归一后是同一件。

**这条的坑**：99 Ranch 生鲜页整页没有编码 → 生鲜的跨周身份只能靠名字。
而名字层已知会被模型改写（`SEABASS 鱈魚→鱸魚` 稳定重现）。

## 倒着验的结果 —— 缺口清单

**这是本文档最主要的产出。** 拿上面七棵树的叶子，逐条问「有哪列接住了」：

| 需求 | 状态 | 说明 |
|---|---|---|
| 规格上限（区间另一头） | ❌ **缺口** | `sizes` 存的是原样字符串（`24.3 to 27.3 oz`），没有拆出上下限的字段。Safeway 22% 受影响 |
| 一格几件商品 | ❌ **缺口** | `codes` 数组能看出几个编码，但**编码↔规格的对应关系传单没印**，展不开 |
| 一格两个价 | ❌ **缺口** | `5 FOR $5 │ $9.99/CS`，`price` 单值装不下（FieldSet §十 挂起）|
| 品牌 | 🟡 **半缺口** | 传单基本不印，靠回连商品库（`brandName` 91%）。Flipp `brand` 67% |
| 跟原价比 | 🟡 **半缺口** | Ranch 传单 12%、Flipp 0%。**说不出「省了多少」** |
| 跟平时比 | 🟡 **半缺口** | 历史一条没攒，且历史里只有特价 → 只能说「比平时特价便宜」 |
| 跟替代品比 | 🟡 **半缺口** | 要分类 + 实体识别，比「认同一件」难一个量级 |
| 会员价 | 🟡 **半缺口** | Flipp 混在 `price_text` 自由文本里（`ea member price`），要解析 |
| 规格（Flipp）| 🟡 **半缺口** | 只存在于 `description` 自由文本里，Ranch 是结构化的，**形态不同要写解析** |
| 库存 / 有没有货 | ❌ **能力缺口** | 传单不印。商品库 `available` 100%，但那是商品库不是传单 |
| 单品级时间限制 | ⬜ **没见过** | 目前只见过页面级（`Friday. Saturday. Sunday ONLY`）|
| 跨店匹配 | ⬜ **没验过** | 「跟别家比」整支压在它上面，从没测过能到什么水平 |

**产品层要知道的**：

```
Safeway 22% 的商品做不了跨店比价      规格是区间，折算不出唯一单品规格
四家店都说不出「省了多少钱」          原价覆盖 12% / 0%
Flipp 三家没有商品层（条码/分类/产地/中文名/库存）  那三家的这一整层永远空
```
